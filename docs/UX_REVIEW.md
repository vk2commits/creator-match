# 사용자 피드백 이후 UX 재설계

2026-09-21. 사용자가 실제 첫 구현을 보고 지적한 사항을 출발점으로 재설계했다. AI의 자체 발견이나 사용자 테스트 인터뷰로 꾸미지 않는다.

## 첫 구현의 문제

| 문제 | 사용자에게 생기는 비용 | 수정 |
|---|---|---|
| 곧바로 점수 목록 진입 | 내가 원하는 캠페인과 기준의 연결이 없음 | 첫 캠페인 설정에서 우선순위 선택 |
| 고정 35/35/20/10 | 근거 없는 기본값이 객관적 정답처럼 보임 | 무선택 상태로 시작, 목적별 프리셋과 균등 비교 제공 |
| 환산값·내부 ID 전면 배치 | 선택보다 계산을 해독하게 만듦 | 판단 언어로 요약, 계산은 상세의 추가 펼침 |
| 동일 안내 반복 | 중요한 차이가 묻힘 | 예산 안내는 조건과 목록 제목에 한 번 |
| 긴 카드의 반복 | 후보 간 지표 비교가 어려움 | 데스크톱 정렬된 목록, 3명까지 비교 |
| 탐색 뒤 다음 행동 없음 | 확인 후 무엇을 해야 할지 모름 | 검토 후보 담기·비교 메모 내려받기 |
| 금액 쉼표 거절 | 익숙한 금액을 다시 해석해야 함 | 자동 천 단위 표시, 쉼표 붙여넣기 허용 |
| 업계 명칭 우선 | 신규 광고주가 규모를 추측해야 함 | 팔로워 구간 우선, 과제 필수 용어는 보조 |
| 누적 예산 미노출 | CSV 필드 활용 누락 | 상세에 원본 누적 집행액 표시, 산술 불일치 주석 |
| 실제 채널 이동 없음 | 최종 콘텐츠 적합성 확인 불가 | 제공 URL 없음 명시, 실제 서비스 추가 필드로 설계 |

## 여정

서비스 가정: 가입 완료 → 첫 캠페인 우선순위 → 분야·예산·팔로워 조건 → 후보 탐색 → 상세 확인 → 2~3명 비교 → 검토 후보와 판단 근거 보관 → 실제 채널/견적 확인.

이번 데모는 가입 완료 직후부터 시작한다. 인증이나 실제 문의를 수행한 것처럼 보여주지 않는다. 첫 방문은 추천 기준을 먼저 선택하고, 재방문은 이 브라우저에 저장된 조건으로 돌아온다. 예시 바로 보기는 균등 비교라는 선택을 명시해 우회할 수 있다.

## 추천 기준 변경

35/35/20/10은 콘텐츠 신호를 중심에 둔 초기 가설이었지만 실증된 기본값이 아니다. 사용자가 문제를 지적했고 AI가 고정 기본 노출을 기각했다. 현재 선택지는 다음과 같다.

- 콘텐츠 반응: 참여율50 / 조회수25 / 평점15 / 경험10.
- 조회 규모: 참여율20 / 조회수55 / 평점15 / 경험10.
- 협업 이력: 참여율20 / 조회수20 / 평점30 / 경험30.
- 균등 비교: 모두25. 아직 우선순위를 정하지 않은 사용자가 명시적으로 선택한다.

수치는 프리셋의 의도를 구현하는 설계 가정이며 성과 예측이나 학습 결과가 아니다. ‘도달 목표 달성’·‘안전한 협업 보장’ 등의 주장은 하지 않는다. 플랫폼·규모 상대 위치를 쓰므로 절대 조회수 최대화와 다르며 원지표 정렬을 유지한다. 데이터 부족으로 구매·브랜드 적합성·진성 팔로워 목표는 제공하지 않는다.

## 정보 구조

목록: 이름, 플랫폼 아이콘+접근 가능한 이름, 분야 태그, 팔로워, 조회수, 참여율, 이력·평점, 과거 평균 비용. 숫자를 같은 열에 정렬한다.

상세: 근거와 확인할 점 → 전체 지표 → 누적 집행액 → 가격·평점 해석 → 계산 상세/원본 식별자. 계산만 숨기고 판단에 필요한 불확실성은 숨기지 않는다.

비교: 같은 행에서 최대 3명 비교. 지표별 최고값은 관측된 우세일 뿐 ‘최고의 크리에이터’로 표시하지 않는다. 조건 변경 후 담은 후보는 유지하되 현재 적격 여부를 다시 표시한다.

| 필드 | 노출/사용 |
|---|---|
| creator_id | 내부 키·안정 정렬·상세의 원본 정보·비교 파일 |
| creator_name | 목록·상세·비교 |
| category | 태그·입력 필터 |

| followers | 이름 아래 규모·필터·상세 |
| avg_view_count | 목록·상세·비교·점수 |
| engagement_rate | 목록·상세·비교·점수 |
| total_campaign_count | 목록·상세·비교·점수 |

| advertiser_rating | 목록·상세·비교·점수, 공란은 미평가 |

## 카피 원칙과 전후

- “숫자 너머의 가능성” → “이번 캠페인에서 무엇을 우선할까요?”
- “환산 93.2×0.35” → “같은 플랫폼·규모에서 참여율이 높은 편이에요” (근거 충족 시에만).
- “쉼표 없이 입력” → 입력 자체에 쉼표 적용.
- “현재 견적 확인 필요” 반복 → 열 제목 ‘과거 평균 비용’, 공통 안내 ‘실제 견적과 다를 수 있습니다’.
- “견적 확인 필요” 후보 상태 → ‘비용 미확인’; 이유는 해당 탭에서 설명.
- “선택한 분야 중 하나라도 일치” → ‘분야 · 복수 선택’. OR 정책은 기획 문서에 보존.
- 확률·매출·보장 표현을 쓰지 않는다. 플랫폼은 아이콘만으로 접근성을 잃지 않게 이름을 함께 제공한다.

[Onboarding vs contextual help](https://www.nngroup.com/articles/onboarding-tutorials/)는 긴 설명형 투어 대신 실제 첫 작업을 설정하고 결과 옆에서 기준을 변경하도록 한 판단에 참고했다. 일반 UX 원칙이며 이 사용자 집단에 대한 검증 결과는 아니다.

남은 검증: 실제 광고주 3~5명이 조건 설정·후보 비교·선정 이유 설명을 수행하도록 관찰. 현재는 지원자 피드백과 자동/브라우저 검증까지만 수행한다.
