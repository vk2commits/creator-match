# 10차 제품 개선 · 작은 분석 버튼과 캠페인 적합 문단 · 2026-09-22

사용자의 최신 요청은 큰 분석 배너를 줄이고 크리에이터·제품·타깃이 왜 연결되는지 한 문단으로 읽히게 하는 것이었다. 기존 지표 중심 첫 판단을 수정했다.

- 카드의 분석과 저장 버튼은 같은 높이. 관심 후보를 누를 때만 분석을 연다.
- 첫 문단은 후보 분야·플랫폼, 입력한 제품·타깃·선택 이유, 제안할 장면과 관측 근거를 연결한다. 제품을 보여줄 방식의 제안과 실제 시청자의 특성을 구분한다.
- 패션의 립 제품은 옷차림과 컬러의 연결, 뷰티는 발색·사용감의 확인으로 설명한다. 미평가·예산 초과·분야 불일치도 첫 문단에 반영한다.
- 경쟁사는 [심층 보고서](COMPETITOR_DEEP_DIVE.md)로 보완했다. 6개사 공식 핵심21개·보조2개 자료를 확인했다. 기능 미확인과 명시적 미제공을 구분했다.
- 143개 테스트·타입·빌드 통과, 별도 데스크톱 세션에서 소형 버튼·로딩·두 분야의 문단·문의 초안을 확인했다. 마케터 이해도 실험과 실제 모델 성능 검증은 아니다.

중요한 판단: 적합 설명을 잘 쓰는 것과 실제 오디언스가 맞는 것은 다르다. 첫 문단은 ‘왜 이런 협업을 제안하는가’를 설명하고, 시청자 일치는 채널 인사이트를 받아 검증하도록 연결한다. 더 세밀한 개인별 차이를 만들려면 실제 게시물·광고 사례가 필요하다.

아래는 이전 개선 당시 기록이며 최신 정책은 위 절과 PRD를 따른다.

# 9차 당시 제품 개선 · 요청형 분석과 입력 UX · 2026-09-22

사용자가 카드의 반복 설명, AI 시연 배지, 필수 표시 부재와 성과 저장 동작을 지적했다. 기존 자동 분석 노출 결정을 수정했다. 기능과 내용이 많아진 사실을 사용성 향상의 증거로 보지 않는다. 아래 8차 기록은 당시 결정이며 현재 화면은 이 절과 PRD를 따른다.

## 바뀐 판단과 사용자 행동

| 지적 | 변경 | 확인 근거 |
|---|---|---|
| 카드마다 추천 이유가 비슷함 | 자동 분석·‘추천 목록에 포함된 이유’를 제거. 지표·비용과 분석 버튼으로 축약 | 데스크톱 카드 확인 |

| 필수 정보가 접혀 있으면 찾기 어려움 | 오류가 있는 탭과 접힌 영역을 열고 입력란으로 이동 | 구매0건·집계 기준 누락·펼침 및 초점 확인 |

## 분석이 후보마다 달라지는 근거

200명 원지표, 선택 비중의 실제 점수 구성, 캠페인 입력을 사용한다. 정은매거진77은 조회35,172회·과거 평균78만원·200만원 상한 대비122만원 차액, 서연리뷰66은 참여율8.1%·평균146만원·54만원 차액이다. 같은 플랫폼·규모 내 비교, 낮은 지표, 가격이 확인되는 대안도 실제 데이터에서 정한다. 35/35/20/10 같은 고정 가중치를 새로 추가하지 않았다.

콘텐츠는 관측 사실이 아닌 제안이다. 동일 캠페인의 공통 요청은 남지만 실제 게시물을 본 것처럼 후보별 취향·시청자 구성·판매 가능성을 꾸미지 않는다. 합성 콘텐츠 유형은 새 분석의 입력에서 제거했다. 실제 서비스에서는 허가된 게시물·타깃 인사이트와 모델 연결 후 품질 평가가 필요하다.

## 지금 단계

9차 구현과 자동·데스크톱 검증 후 사용자 재검토 단계다. 새 시장조사·인터뷰를 했다고 주장하지 않는다. 기존28개 출처와 A/B/C 추천 비교는 유지한다. 모바일 작업·공개 배포·메일 제출은 진행하지 않았다. 사용자가 실제로 분석을 읽고 ‘왜 이 후보인지, 다음에 무엇을 할지’를 설명할 수 있는지는 이번 검토에서 확인해야 한다.

# 8차 당시 제품 검토 · 이전 결정 기록

**이번 목표는 기능 수가 아니라, 브랜드 마케터가 ‘왜 이 후보인가 → 누구에게 문의할까 → 보낸 문의는 어디에 있나’를 설명 없이 따라갈 수 있는 구조다.** 사용자의 지적을 반영해 구현하고 AI가 데스크톱 과업을 점검했다. 사람 대상 이해도·만족도 검증과 과제 제출은 아직 완료되지 않았다.

## 핵심 흐름

캠페인 → 타깃 고객(선택) → 후보 조건 → 추천 비중 → 조건·계산 절차 안내 → 캠페인 분석과 실제 추천 이유 → 후보 저장·비교(선택) → 한 명에게 문의 → 보낸 내역 → 답변·조건·제작 → 성과 기록.

‘팀 검토안이 필요하다’는 이전 가정은 실제 근거 없이 추가된 것이었다. 사용자 피드백에 따라 팀 검토안과 문의 후보 별도 분류 UI를 제거했다. 저장 인원·비교 인원·발송 건수는 각각 그 자리의 행동을 정확히 센다.

## 추천 설계와 연결되는 차별점

1. 사용자의 기준을 명시적으로 적용하고, 계산의 근거를 읽기 쉬운 강점·약점으로 설명한다. 같은 데이터에서 우선 기준에 따라 다른 후보가 앞선다.
2. 예산 미확인·평점 미평가를 추천 실패가 아닌 별도 검토 경로로 처리한다. 알려지지 않은 것을 좋은 수치로 꾸미지 않는다.
3. 캠페인 분석은 콘텐츠를 어떻게 활용할지 제안하고, 실제 지표는 왜 추천 후보인지 설명한다. 둘은 같은 사실이 아니므로 구분한다.
4. 추천에서 끝나지 않고 개별 문의·보낸 문안·협업·성과로 이어지되, 팀 검토안처럼 이번 페르소나의 필요가 확인되지 않은 중간 단계를 제거한다.

이 차이는 구현·문서의 설계 선택이다. 다른 지원자의 제출물을 본 적이 없으므로 ‘경쟁 지원자보다 우수하다’고 주장하지 않는다.

## 지금 단계와 남은 판단

8차 구현·자동 검사·데스크톱 핵심 과업 점검까지 완료했다. 새로운 시장조사나 마케터 인터뷰를 했다고 주장하지 않는다. 기존 [리서치](RESEARCH.md)의 28개 출처와 비교 실험을 유지했다. 판단의 주된 새 근거는 사용자의 반복적인 실제 화면 피드백이다.

다음은 기능을 더 추가하기 전에 사용자와 다음 세 과업을 확인하는 단계다.

- 첫 카드에서 캠페인에 맞는 이유와 실제 데이터 근거를 각각 말할 수 있는가?
- 세 명 중 한 명에게 문의하고 보낸 문안을 다시 찾을 수 있는가?
- ‘AI 시연’과 원본 지표, 실제 집행 성과를 혼동하지 않는가?

설명 없이 멈추는 위치와 이해하지 못한 문구를 기록한다. 실사용 검증 전까지 직관성이 입증됐다고 쓰지 않는다. 공개 저장소·최종 제출·면접 연습은 별도 남은 단계이며 모바일 작업은 하지 않았다.
