# 6차 UX 재검토: 숫자를 읽는 화면에서 후보를 판단하는 화면으로

2026-09-21. 지원자가 5차 화면을 보고 이해하기 어렵다고 지적했다. 기능과 자동 테스트가 늘어난 사실은 사용성 개선의 증거가 아니었다. 이번 변경은 추천의 설계 근거를 사용자의 의사결정 순서로 보여주는 데 집중한다. 모바일 추가 작업은 하지 않았다.

## 어떤 문제가 있었나

| 지원자의 관찰 | 원인 | 바꾼 경험 |
|---|---|---|
| AI 브리프가 미연결이고 버튼의 쓸모가 안 보임 | 개발 준비 상태가 사용자의 업무를 막음 | AI 시연 → 문장 입력 → 수정 가능한 제품·조건 초안 → 적용 → 실제 추천 |
| 자료 확인에 코드가 보임 | 개발자가 검증할 자료와 사용자 입력을 혼동 | JSON·환경변수·다른 AI 요청문을 화면에서 제거 |
| 중간값 4.1배가 무슨 뜻인지 모름 | 계산 설명을 추천 이유로 대신함 | 중요한 지표의 강점 + 분야·예산 적합 + 다음 확인 행동 |
| 중요한 지표가 안 보임 | 모든 숫자의 시각적 무게가 같음 | 최고 비중 지표를 상단과 카드에서 ‘중요’로 표시 |
| 담은 다음 행동이 불명확함 | 담기·비교 체크·문의 상태의 역할이 보이지 않음 | 텍스트 버튼, 최대3명 비교 안내, 한 명의 ‘문의 준비’ 바로가기 |
| 문의 준비가 긴 양식임 | 지금 필요한 결과물보다 기록할 필드가 먼저 나옴 | 보낼 문안을 먼저, 제작 조건·연락처·진행 상태는 펼침으로 이동 |
| 성과 리포트의 사용법을 모름 | 빈 통계 카드가 첫 화면임 | 후보 선택 → 조회수·비용 입력 → 결과 비교 안내와 완성 예시 |
| 온보딩 로딩이 보이지 않음 | 실제 계산이 너무 빨라 전환을 인지할 수 없음 | 1.6초 전환 화면, 실제 Worker 대기·오류는 별도로 유지 |

## 페르소나와 판단 단위

브랜드 실무 마케터가 이번 제품의 협업 후보를 고르고 팀에 선정 이유를 설명하는 과업이다. 따라서 화면은 ‘점수가 몇 점인가’보다 다음 질문에 답해야 한다.

1. 내가 찾는 분야와 예산에 들어오는가?
2. 내가 중요하게 고른 지표에서 어떤 근거가 있는가?
3. 그 근거만으로 알 수 없는 것은 무엇이며 다음에 무엇을 확인하는가?
4. 이 후보를 검토 대상으로 남길지, 실제 문의를 준비할지?

페르소나는 지원자의 직접 선택이다. 이번 브라우저 점검은 AI의 과업 수행 검증이며 실제 마케터 인터뷰나 사람 대상 사용성 실험이 아니다.

## 실제 후보에서 어떻게 달라지는가

조회수 우선·뷰티/패션·팔로워 1만~10만 미만·1명당 200만원에서 정은매거진77을 먼저 추천한다. 채널 평균 조회 35,172회, 참여율 6.5%, 집행 24건, 광고주 평점 5.0, 참고 협업비 78만원이다.

화면의 첫 판단은 **‘조회 실적이 돋보이는 후보’**다. 비슷한 규모의 인스타그램 채널에서 조회수가 높은 편이라는 관찰과, 선택한 조회수 우선 기준을 연결한다. 선택한 패션 분야에 속하고 과거 평균 협업비가 예산 안임을 별도로 설명한다. 반대로 참여율은 해당 비교 집단에서 상대적으로 낮으므로 최근 댓글의 제품 관심을 확인하라고 안내한다. 모든 후보를 무조건 좋은 후보처럼 설명하지 않는다.

참여율 우선으로 바꾸면 서연리뷰66이 먼저 보이며 중요 지표와 설명이 함께 바뀐다. 이것은 사용자 기준에 따른 추천 순서의 변화이며 실제 구매 성과 우열을 검증한 결과가 아니다.

추천 설명의 대표 지표·보조 강점·높음/중간/낮음 구간은 [PRD](../PRD.md)에 정확히 정의했다. `matchStory.ts`가 같은 점수 구성요소를 읽어 카드·상세·비교표·팀 검토안에 공급한다. 원본 숫자와 점수는 바꾸지 않는다. AI 문안이 순위에 개입하지 않는다.

## 시연과 사실의 경계

- AI 기본 경로는 **AI 시연**으로 표시한 로컬 규칙 기반이다. API 준비 안내를 없애면서도 실제 모델이 실행됐다고 쓰지 않는다.
- 브리프 시연은 명시된 1명당 예산·분야·팔로워 조건을 추출한다. 총예산을 임의로 나누지 않고, 없는 조건은 제안값임을 알린다. 제품 문장과 조건을 함께 수정하고 적용한다.
- 문의 시연은 금액·일정·사용권과 사용자 문장을 보존한다. 내부 평점·가격 비교·선정 이유는 팀 검토안에 남기고 외부 문의에 자동 포함하지 않는다. 이 분리는 AI가 실제 흐름을 점검하며 추가로 발견·수정했다.
- 채널 미리보기는 시연용 콘텐츠로 표시한 로컬 예시다. 실제 계정 URL·사진·영상·댓글을 수집했다고 주장하지 않는다. 실제 콘텐츠를 연결해야 브랜드 표현과 고객 취향을 평가할 수 있다.
- 성과 예시는 저장하지 않는다. 실제 입력 결과, 추천용 CSV, 시연용 수치를 구분한다. AI 요약도 입력된 숫자만 문장으로 바꾼다.
- 온보딩 1.6초, AI 시연 0.9초는 설명을 읽기 위한 전환 시간이다. 처리 성능이나 AI 분석 퍼센트가 아니다.
- `?demo` 체험 모드는 기존 기록을 읽거나 저장하지 않는다. 기존 사용자 데이터를 덮지 않고 처음부터 체험·검증할 수 있다.

## 기능 추가보다 우선한 정리

카피에서 원본 ID·중간값 배수·환산식·환경변수·JSON을 제거했다. 데이터 사용 근거는 평가자가 읽는 문서에 유지했다. 화면에서 필요한 비용의 불확실성은 ‘참고 협업비는 과거 평균, 최종 견적은 문의’로 설명한다. Pro 잠금·결제·가입·더 많은 대시보드 기능을 추가하지 않았다. 추천과 사용자의 판단이 과제의 중심이기 때문이다.

기존 28개 공식 중심 출처와 경쟁사 비교는 유지한다. 이번 변경 근거는 추가 경쟁 기능 발견이 아니라 지원자의 구체적인 사용성 피드백이다. 조사 건수를 늘렸거나 새 사용자 인터뷰를 했다고 쓰지 않는다.

## 다음 사용자 검토

새 체험 모드에서 설명 없이 다음 과업을 수행해 보는 것이 다음 단계다.

1. AI로 캠페인 조건을 만들고 틀린 조건이 있으면 수정한다.
2. 첫 후보를 왜 추천했는지, 자신의 말로 설명한다.
3. 기준을 바꿔 순위와 설명 변화가 납득되는지 확인한다.
4. 한 명을 골라 문의 문안을 준비한다.
5. 성과 예시를 보고 다음에 직접 입력해야 할 내용을 찾는다.

완료 기준은 화면 수가 아니라 사용자가 ‘왜 이 후보인지’와 ‘다음에 무엇을 해야 하는지’를 설명할 수 있는가이다. 이 사용자 검토, 실제 모델 품질, 실제 콘텐츠·연락 연결, 공개 저장소 제출은 아직 완료하지 않았다. 다른 지원자 결과물을 보지 않았으므로 독점적 차별성이나 더 높은 과제 점수를 보장하지 않는다.
