## 점수 가설

초기 참여율35/조회35/평점20/경험10 고정 기본값은 지원자의 실제 피드백으로 기각했다. 현재는 첫 설정에서 콘텐츠 반응(50/25/15/10), 조회 규모(20/55/15/10), 협업 이력(20/20/30/30), 균등 비교(25/25/25/25)를 선택한다. 비중은 의도를 표현한 가정이며 실증된 최적값이 아니다. 76개 비어 있지 않은 조건 중 34개는 선택 기준에 따라 1위가 달랐다. 전체 CSV와 적격 조건은 바꾸지 않는다. 예산·카테고리·규모는 필터이므로 다시 가산하지 않는다. 누적 예산과 팔로워는 중복 규모 가산을 피하기 위해 점수에 추가하지 않는다.

상대 위치는 동점을 중간 순위로 처리해 0~100에 배치한다. 전체 원본의 플랫폼×규모 집단을 고정해 사용자 필터에 따라 같은 후보 점수가 바뀌지 않게 한다. 최소 표본은 10명으로 정한다. 미달이면 같은 플랫폼 전체, 그것도 미달이면 전체 집단을 사용하고 집단 이름·표본 수를 노출한다. 기준은 제품 가정이며 현재 6개 집단은 13~69명으로 모두 10명 이상이다.

평점은 (평점-1)/4×100, 공란은 척도 중간값인 50점의 계산상 대체값을 사용하고 관측값처럼 표시하지 않는다. 집행 경험은 log(1+건수)/log(1+전체 최대 건수)×100으로 체감 가산한다. 캠페인 건수를 평점 표본 수로 간주하는 베이지안 보정은 도입하지 않는다.

견적 미확인 후보는 종합 추천 점수를 표시하지 않고 평균 조회수 내림차순, 동률이면 ID 오름차순으로 정리한다. 이 영역은 예산을 충족한 추천 후보와 합치지 않는다.

후속 비교 실험에서 복잡성이 설명 이점을 상쇄하면 단순 방식으로 수정할 수 있다. 변경 시 이 기록과 PRD·코드·테스트를 함께 갱신한다.


## D12~D16 — 전체 검토 후 적용 · 2026-09-21

- D12: 추천 설명의 비교 집단·중간값을 점수 결과와 공유한다. 예산 산술 설명도 후보별로 분기한다. 설명은 계산과 별개로 검증해야 한다는 반례를 반영했다.
- D13: 세 우선 기준을 주 선택지로 두고 균등은 보조로 제공한다. 기존 숫자 가중치는 유지하며 별도 최적성 주장을 하지 않는다.
- D14: 보관에는 3명 제한을 두지 않고 동시 비교만 3명으로 제한한다. 사용자 판단을 후보별로 직접 기록·복사하며 브라우저에 보존한다.
- D15: Pro는 반복 캠페인·견적·팀 검토 가치로 PRD에 설계한다. 핵심 추천을 잠그거나 4번째 보관을 과금하지 않는다. 유료 기능·가격·결제는 미구현이다.
- D16: 제품 AI는 브리프 조건 정리→사용자 확인→고정 추천 함수의 선택 경로로 설계한다. 현재 앱의 실제 모델 호출은 없고 해당 검증 계획은 향후 항목이다.

사용자가 ‘개선점을 적용시켜’라고 요청한 뒤 AI가 구현했다. 지원자가 최종 UI 만족·가중치 설명·제출을 승인한 것으로 확대 해석하지 않는다.


## D17. 브랜드 실무 마케터와 문의 준비의 완결성

사용자가 주 사용자로 브랜드 실무 마케터를 선택했다. ‘협업 경험이 있고 내부에 문의 후보와 이유를 설명한다’는 행동 가설을 명시하고 실제 인터뷰 결과와 구분했다. 최종 산출물을 팀 검토안으로 정의하고 검토 중/문의 후보/보류와 직접 작성 이유를 연결했다. 1명도 완료 가능해야 하므로 상세에서 직접 진행하는 경로를 추가했다.

프리셋만 제공하면 쉽다는 가정은 근거가 부족했다. 프리셋과 직접 비중 조절을 병행하고 합계100·시작 비율 재분배·미리보기·취소로 조작을 명확히 했다. 0%인 지표를 설명에 근거로 쓰지 않는다. 추천의 정확성이 좋아졌다고 주장하지 않는다.

상세의 공통 선정 전 체크리스트는 팀 검토안으로 옮기고 후보별 결측·조건만 표시한다. 복사할 검토안에 ID·누적액·데이터 산술 설명을 넣는 것은 팀 판단에 불필요해 기각했다. 원본 전체 정보는 상세에 보존했다. 파일 다운로드보다 실제 검증한 미리보기·복사 경로로 단순화했다.

근거: 사용자의 실제 피드백, 구현·72개 테스트·브라우저 과업 점검. [페르소나 문서](PERSONA_TEST.md)의 실제 마케터 테스트는 미수행이다.

## 5차 결정 · 캠페인 업무 연결

- 캠페인 목적을 온보딩에 추가하되 추천 수식의 정답 라벨처럼 쓰지 않는다. 목표별 프리셋은 수정 가능한 시작점이다.
- 사용자 요청에 따라 직접 비중을 마지막 단계에 기본 공개한다. 계산 수식의 최적성을 주장하지 않는다.
- Modash의 수동 상태 관리·피처링의 소통과 리포트를 참고해 협업 흐름을 잇는다. 자동 발송·자동 수집을 흉내 내지 않는다.
- 기록한 성과는 CSV·추천 가중치에 합치지 않는다. 비용과 지표의 관측 범위가 맞는 경우에만 효율을 계산한다.
- AI는 브리프·문의·요약 초안을 맡는다. 추천·연락·재계약은 자동 결정하지 않는다. 연결은 구현했지만 실제 모델 품질 검증은 미완료다.
- 가격표·Pro 잠금·모바일 확장은 추가하지 않는다. 반복 캠페인·팀 권한·자동 수집에 유료 가치를 두는 가설은 유지한다.
- 근거, 배제한 질문, 남은 실험은 [5차 UX 검토](WORKFLOW_REVIEW.md)와 PRD에 기록한다.
