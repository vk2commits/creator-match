# 브랜드 실무 마케터: 가설 페르소나와 업무 검증

2026-09-21. 사용자가 브랜드 실무 마케터를 주 사용자로 선택했다. 업무·도구·행동 특성은 검증 전 가설이다. 실제 인터뷰나 마케터 행동 관찰을 수행한 페르소나가 아니다.

## 현재 8차 페르소나와 과업 · 2026-09-22

주 사용자는 브랜드 실무 마케터다. 제품·예산을 바탕으로 크리에이터를 추리고 견적을 문의한다. **팀 승인과 검토안 작성이 반드시 필요하다는 이전 가정은 기각했다.** 현재 과업은 캠페인에 맞는 이유를 이해하고, 필요하면 2~3명을 비교한 뒤 한 명에게 문의하며 보낸 내역을 찾는 것이다. 협업 후 직접 확인한 성과를 기록한다.

검증 계획: 실제 마케터 2~3명에게 사용법을 먼저 설명하지 않고 후보 선택→개별 문의→보낸 문안 재확인을 요청한다. 선택 이유, AI 시연과 원본 지표의 구분, 예산이 확정 견적인지, 비중 변경의 의미를 스스로 설명하게 한다. 도움 요청과 멈춤 지점을 관찰하며 시간·성공률은 실제 수행 후만 기록한다. 인터뷰·참여자 모집은 아직 하지 않았다.

현재 AI 데스크톱 기능 검증은 네 단계 이동, 비중 취소/적용, 카드·상세 분석 기본 노출, 3명 비교에서1명 문의, 보낸3건 재열기까지다. 자세한 증거는 [QA](QA.md), 요소별 이유는 [8차 검토](PRODUCT_UX_AUDIT.md)에 기록한다. 아래는 4~5차의 당시 가설·기능 검사 이력이며 현재 정책으로 읽지 않는다.

## 이전 버전의 가설과 검토 기록

## 1. 누구의 어떤 업무인가

| 항목 | 제품 가설 | 설계에 주는 의미 |
|---|---|---|
| 역할 | 브랜드에서 크리에이터 협업을 직접 운영하는 실무 마케터 | 브랜드/한 캠페인 단위의 후보 검토에 집중 |
| 상황 | 제품 캠페인의 분야·예산을 전달받아 견적 문의 대상을 추림 | 과거 비용과 확정 견적을 구분해야 함 |
| 경험 | 참여율·조회수·광고주 평점을 이해하고 스프레드시트로 비교한 경험이 있음 | 프리셋과 직접 비중 조절을 모두 제공할 이유 |
| 권한 | 후보 제안·견적 문의는 할 수 있으나 계약·최종 예산 승인은 팀 검토 필요 | 결과는 최종 계약이 아닌 문의 후보와 검토안 |
| 원하는 결과 | 누구에게 왜 문의할지, 비교에서 제외한 이유와 미확인 정보 설명 | 보관 → 비교 → 문의 후보 지정 → 이유 작성 → 팀 검토안 복사 |
| 현재 대안 | SNS·스프레드시트·팀 메시지에서 후보와 이유 취합 | 목록 탐색만으로는 기존 방식보다 업무 완결성이 높아지지 않음 |
| 범위 밖 | 완전 입문자에게 광고 전략 수립, 대행사의 다중 브랜드 승인, 직접 계약·발송 | 초점 없는 온보딩·다수 워크스페이스·가짜 문의 버튼 제외 |

완료할 업무: **분야·팔로워·1명당 예산에 맞는 후보를 검토하고, 문의할 대상과 이유를 팀에 전달할 검토안으로 정리한다.** 후보를 담는 것은 중간 단계다. 실제 문의·채널 확인·계약은 별도 업무이며 더미 데이터로 실행하지 않는다.

## 2. 이전 구현에 대한 과업 검토

검토자는 AI다. 아래는 코드·화면의 행동 경로에 대한 평가이지 인간 사용자의 성공률 측정이 아니다.

| 과업 | 이전 상태의 문제 | 수정 기준 |
|---|---|---|
| 재방문해서 온보딩 보기 | 저장된 조건으로 건너뛰지만 재진입 링크 없음 | 항상 보이는 ‘캠페인 설정’, 직접 링크, 취소 시 기존 조건·후보 유지 |
| 내 캠페인에 맞게 기준 조정 | 네 프리셋만 가능. 숙련 사용자에게 선택권이 부족 | 프리셋+드래그/숫자/키보드로 비중 조절, 합 100%, 적용 전 결과 확인 |
| 후보 상세의 의미 파악 | 모든 후보에 같은 확인 목록 반복 | 후보별 결측·현재 조건 상태만 상세에, 공통 정보는 검토안에 한 번 |
| 담은 뒤 결정 | 보관과 비교·메모가 있지만 문의 대상 결정 상태 없음 | 검토 중/문의 후보/보류를 분리하고 결과물에 실제 결정을 반영 |
| 후보 1명만 남음 | 비교 2명부터 시작하는 흐름만으로는 종료 불가 | 상세에서 문의 후보 지정, 1명으로도 검토안 완성 |
| 판단 전달 | 메모 복사 후 무엇을 하는지 불명확 | ‘팀 검토안’ 명명, 대상·선정 이유·기준·미확인 정보 포함 |

## 3. 프리셋과 슬라이더: 검증할 가설

프리셋을 택했던 이유는 첫 입력의 부담을 줄이려는 가정이었다. 더 좋다는 사용자 근거는 없다. 직접 조절은 기준이 있는 마케터의 통제감을 높일 수 있지만, 정확한 %가 정확한 성과를 뜻한다는 오해와 순위 맞추기 위험이 있다. 어느 쪽이 더 나은지는 사용자 과업으로 비교해야 한다.

권장안: 첫 사용에는 프리셋으로 시작할 수 있고 ‘직접 비중 조절’도 선택 가능. 결과에서 언제든 조절. 한 값을 바꾸면 나머지는 기존 비율에 따라 재분배하고 합계는 100%. 이를 명시하고 네 값을 항상 함께 보여준다. 정수 반올림 잔여는 큰 소수 부분 순으로, 동률은 고정 지표 순으로 배분한다. 다른 세 값이 모두 0이면 균등 배분한다. 한 번의 조작 중에는 시작 비율을 기준으로 계산해 반복 반올림의 쏠림을 막는다. 수동 입력·키보드도 제공한다. 적용 전 상위 후보 미리보기, 취소 시 현재 결과 유지. 이는 조작 가능한 설계 가정이며 최적 비중 검증이 아니다.

## 4. 이번에 실행한 과업과 판정

| ID | 시나리오 | 통과 조건 | 수행 주체 |
|---|---|---|---|
| P01 | 기존 저장이 있는 상태에서 온보딩 재진입 후 취소 | 재진입 가능, 기존 조건·보관·판단 유지 | AI 브라우저 기능 점검 |
| P02 | 뷰티·패션 / 1만~10만 / 200만원. 참여와 조회 우선 비교 | 동일 적격 21명, 순위와 기준 설명 일치 | AI 브라우저·자동 계산 |
| P03 | 조회수 비중을 직접 조절·취소·재적용 | 합 100, 후보 집합 동일, 미리보기=적용 결과, 직접 기준 저장 | AI 브라우저·자동 계산 |

| P05 | 문의 후보가 1명뿐인 경우 | 가상의 비교 상대 없이도 이유 작성·검토안 복사 가능 | AI 브라우저 |
| P06 | 비용·평점 미확인 후보 | 모르는 정보와 예산 판정 불가를 표시, 문의 대상으로는 선택 가능 | AI 브라우저·자동 계산 |

P01~P06의 위 기능 판정은 통과했다. [QA](QA.md)에 실제 브라우저 수행과 자동 계산 범위를 구분했다. 관찰한 사례:
- P01: 저장된 참여율 기준에서 재진입해 조회수100%로 바꾼 뒤 취소 → 기존 기준·보관 유지.
- P02/P03: 200만원·뷰티/패션·1만~10만에서 21명/미확인3명. 조회수100% 적용 전후 상위3은 정은매거진77·시우매거진155·소민푸드로그175, 새로고침 후 동일. 프리셋 간 동일 자격 집합은 자동 계산으로도 검증.
- P03: 실제 드래그·숫자 입력·화살표/End 조작, 취소, 적용. 예산100만원으로 변경 후 직접 비중 유지·적격8명.
- P04: 정은매거진77 문의 후보, 서연리뷰66 보류, 각 이유 작성. 검토안에 대상과 보류가 구분되고 재방문 후 상태 유지.
- P05: 정은매거진77 한 명만 있어도 상세에서 문의 이유 작성·복사. 이유 공란일 때는 복사를 막고 작성할 항목 안내.
- P06: 지수챌린지36 문의 후보 지정. 검토안에는 비용 미확인·예산 판정 불가·추천 순위 비교 제외가 남음.

AI 점검으로 추가 발견·수정: 직접 비중이0%인데도 반영한다고 말하는 기존 설명, 비교 문구의 조사 오류, 포인터 이동마다 반올림해 세 비중이 쏠리는 현상. 드래그 시작 비율을 고정해 수정 후 재확인했다. 인터뷰·성공률·시간 단축 수치를 만들어내지 않는다.

## 5. 실제 마케터에게 검증할 계획 — 미수행

대상: 크리에이터 협업 후보를 직접 추려본 브랜드 실무 마케터 2~3명. 접촉·모집은 사용자 명시 요청 없이 수행하지 않는다. 표본이 작으므로 통계적 일반화를 하지 않는다.

방법: 화면 사용법을 먼저 설명하지 않고 ‘뷰티 캠페인에서 1명당 200만원 안으로 문의할 후보를 정하고 팀에 선정 이유를 전달해 달라’는 과업을 제시한다. 프리셋만 있는 안과 직접 조절 가능한 안의 제시 순서를 참여자마다 바꾼다. 브리프는 가능한 한 실제 업무와 비슷한 난이도로 맞춘다.

관찰: 첫 클릭, 기준 선택 이유, 직접 조절의 필요성, 합계 재분배 이해, 선택한 기준이 결과에 미친 영향 설명, 담기/문의 후보 구분, 과거 비용의 의미, 검토안 전달 완료, 도움 요청·되돌아감·오류. 시간은 실제 수행 후 기록하며 사전 개선율을 넣지 않는다.

검증 질문: ‘무슨 기준으로 이 후보를 골랐나요?’, ‘이 금액으로 바로 계약할 수 있나요?’, ‘복사한 검토안은 어디에 어떻게 쓰겠나요?’, ‘직접 조절이 실제로 필요했나요?’. 긍정적인 답을 유도하지 않는다.

수정 기준: 사용자가 다음 행동을 설명하지 못하면 CTA·단계 재설계. 비중을 성과 확률로 오해하면 설명·제어 방식을 재검토. 실제로 비중 조절 수요가 없고 혼란만 늘면 결과 화면의 보조 옵션으로 낮춘다. 공통 확인 정보가 읽히지 않으면 더 반복하기보다 실제 문의 준비 시점과 연결한다.

## 5차 확장 과업 · 문의 이후 실제 업무

주 사용자는 계속 브랜드 실무 마케터다. 업무 가설을 후보 검토에서 문의 문안·협의 기록·성과 정리까지 연결했다. 경쟁 근거와 질문의 위치는 [5차 검토](WORKFLOW_REVIEW.md)를 참고한다.

| 과업 | 실제 확인 | 남은 확인 |
|---|---|---|
| 브리프→조건→비중 | 3단계 이동, 조회수80%에서9/80/7/4, 적격21명·미확인3명 | 사람의 입력 부담·이해도 |
| 문의 준비 | 복사 후 문의 준비 유지, 실제 날짜 없는 진행 저장 차단 | 실제 이메일 앱의 발송·응답 연동은 범위 밖 |
| 조건 합의→성과 | 날짜·비용·제작 범위와 합성 성과 저장·표시 | 실제 운영 계약·지표의 신뢰도 |
| 성과 상세 | CPV10원·CPE666.67원·CPC200원·CPA10000원·입력매출비200% | 실제 광고 성과 아님. 검증용 값은 제거 |
| 예시 리포트 | 예시 표시, 내 기록과 분리, 입력 없음으로 복귀 | 실제 사용자 시연 |
| AI 다듬기 | 미연결 안내·생성 비활성·요청문 복사 경로 | API 연결 후 출력 평가 |

AI의 과업 점검이며 실제 사람이 이해했다는 증거가 아니다. 앞으로 ‘연락은 무엇이 발송한 것인가’, ‘비중80%는 무엇을 뜻하는가’, ‘조회 평균과 이번 광고 조회수를 비교해도 되는가’를 사용자에게 설명하게 하고 오해를 관찰한다.
