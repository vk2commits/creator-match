# Creator Match

**브랜드 실무 마케터가 후보의 선정 이유부터 문의·협업·집행 결과까지 이어가는 크리에이터 탐색 프로토타입.**

캠페인 → 타깃 고객 → 후보 조건 → 추천 기준·직접 비중 → 탐색·비교 → 문의 준비 → 협업 관리 → 성과 리포트로 이어진다. 제공된 더미 200명의 추천과 수동 기록은 API 키·계정·DB 없이 실행한다. 제품 내 AI 흐름은 로컬 규칙으로 조건·분석·문안·요약을 만들어 적용한다. 실제 모델 호출과 외부 문의 발송은 연결하지 않았다. 화면은 사용자 요청에 따라 별도의 시연 배지 없이 업무 흐름을 보여주며, 구현 범위는 이 문서에 명시한다.

## 3분 안에 살펴보기

1. 아래 명령으로 실행한 뒤 `http://127.0.0.1:5173/?demo`를 연다. **저장하지 않는 체험 모드**라 기존 캠페인 기록을 덮지 않는다. 일반 주소는 브리프·후보·협업 기록을 브라우저에 보존한다.
2. **AI로 초안 만들기 → 예시 문장 넣기 → 초안 만들기**. 편집 가능한 제품·목표를 확인하고 **타깃 고객 정하기**로 이동한다. 고객은 ‘출근 준비 시간을 줄이고 싶은 직장인’, 선택 기준은 ‘내 일상에 대입해요’로 설정한다.
3. **후보 조건 정하기 → 추천 기준 정하기 → 이 조건으로 추천받기**. 조건과 추천 절차를 안내하는 전환 뒤, 추천 21명과 비용 미확인 3명이 나온다.
4. 정은매거진77의 **캠페인 적합 분석**을 누른다. 3단계 로딩 뒤 강점·예산 차이·콘텐츠 구성 제안·협의할 점·비교 후보·성과 계획을 확인한다. **제안 담아 문의하기**로 콘텐츠 제안을 초안에 가져갈 수 있다. **상세 지표**는 원지표와 별도 채널 구성 예시를 연다.
5. **기준·비중 변경 → 반응이 활발한 채널 → 이 기준 적용**. 서연리뷰66이 먼저 나온다. 취소하면 기존 기준을 유지하며, 적용 전 순위 미리보기는 없다.
6. 세 명을 저장하고 **저장한 후보 → 비교표에 추가 → 선택한 3명 비교**. 정확히 세 명의 표와 후보별 **문의하기**가 보인다. 한 명만 있어도 카드·상세에서 바로 문의할 수 있다.
7. **문의 보내기** 뒤 보낸 문안이 바로 펼쳐진다. 왼쪽 **보낸 문의**에서도 다시 확인한다. **답변 받았어요 → 견적·조건 입력 → 협업 확정하기 → 게시 완료로 변경**으로 이어진다. 외부 메일·DM은 발송되지 않는다.
8. 조회수나 집행비를 입력하면 확인일·출처에 `*`가 나타난다. 구매·매출을 입력하면 집계 기준도 필수다. 콘텐츠 주소는 `youtube.com/...`처럼 붙여 넣어도 된다. **저장하고 성과 리포트 보기**는 편집창을 닫고 결과를 보여준다. 리포트에서 다시 수정해 저장해도 동일하다. 또는 **예시 리포트 보기 → AI로 결과 정리**로 완성된 결과를 살펴본다. 원본 CSV에 이 값들을 합치지 않는다.

수동 설정 경로도 유지한다. 상단 **캠페인 설정** 또는 `/#setup`으로 재진입한다. 보관 인원 제한은 없고 동시 비교는 최대 3명이다. 정상 주소의 기존 기록은 온보딩 취소·조건 변경에도 보존한다.

## 실행

Node.js **22.12 이상**, npm이 필요하다. 검증 환경은 macOS / Node 25.5.0 / npm 11.8.0이다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 연다. 기본 주소는 `http://127.0.0.1:5173/`다. `index.html`을 파일로 직접 열면 앱이 실행되지 않는다.

```sh
npm test              # 정책·데이터·저장·로딩 테스트
npm run analyze       # 데이터 감사·추천 비교 문서 재생성
npm run build         # 타입 확인 + dist 생성
npm run preview       # 생성한 dist를 로컬에서 확인
```

별도 폴더에서의 의존성 설치·테스트·빌드 재현과 실제 브라우저 검증 범위는 [QA](docs/QA.md)에 기록한다.

## 세 가지 핵심 판단

**조건과 우선순위를 분리했다.** 예산·분야·팔로워는 반드시 충족할 조건이고, 참여율·조회수·평점·이력은 그 안에서 비교할 기준이다. 참여율 우선, 조회수 우선, 협업 이력 우선, 균등 비교 중 사용자가 선택하거나 네 지표의 비중을 직접 조절한다. 가중치는 설계 가정이며 성과를 학습한 최적값이 아니다.

**모르는 정보를 가격 0원·평점 0점으로 바꾸지 않았다.** 집행 이력 없는 27명은 비용 미확인으로 분리한다. 평균 비용은 과거 참고값이며 현재 견적이 아니다. 평점 공란은 미평가다.

**추천 근거를 협업 판단으로 연결했다.** 카드는 원지표와 비용으로 빠르게 훑고, 분석 버튼에서 왜 검토할 만한지와 구체적인 협업 방향을 확인한다. 분석은 같은 점수 구성요소·원본 지표·캠페인 입력을 읽는다. 콘텐츠 방향은 제안이며, 합성 콘텐츠 유형을 실제 관찰 사실로 쓰지 않는다. 제안을 문의 초안으로 이어가고, 집행 후 입력 결과는 추천 데이터와 분리한다. [전체 화면 검토](docs/PRODUCT_UX_AUDIT.md)에 판단과 검증 범위를 남겼다.

## 알고 있는 한계와 트레이드오프

- 제공 데이터에는 채널 URL·사진·실제 전환·타깃 오디언스·관측 기간이 없다. 실제 계정 링크나 광고 성과를 만들지 않는다. 채널 링크는 별도 로컬 페이지의 콘텐츠 구성 제안을 연다.
- 동일 플랫폼×규모 상대 위치로 비교하되 형식·카테고리·측정 정의 차이는 남는다. 원지표와 정렬을 같이 제공한다.
- 유이력 173명의 평균 비용×건수와 누적액이 일치하지 않는다. 원본은 유지하고 제공 평균으로만 예산을 판정한다.
- 집행 건수는 평점 응답 수가 아니다. 평점 표본이 없는 상황에서 정교한 통계 보정을 가장하지 않는다.
- 점수의 안정성·정책 준수는 검증했지만 실제 추천 정확도·매출 개선·사용자 시간 절감은 검증하지 않았다.
- 인증·실제 문의·계약·다수 크리에이터 총예산 최적화는 제외했다. 첫 설정은 가입 직후를 가정한 데모다.
- 후속 검토에서 발견한 집단 확대의 중간값·신규 후보의 예산 설명을 수정하고 회귀 검증했다. 현재 자동 테스트·빌드 결과는 QA에 기록한다. [QA](docs/QA.md)에 검증 범위와 사용자 리뷰·공개 제출 등 남은 항목을 구분했다.
- 단일 캠페인 작업실이며 1명당 콘텐츠 최신 누적 성과 1건을 저장한다. 다중 캠페인·여러 콘텐츠·시계열·팀 권한·실제 발송·결제·자동 수집은 제외했다. Pro의 가치는 이런 반복 운영 업무의 확장 가설이며 유료 잠금은 구현하지 않았다.
- 추천용 원본 지표와 집행 후 직접 입력한 결과는 서로 다른 데이터다. 기록은 추천 점수에 다시 반영하지 않는다. 원본 평균과 실제 콘텐츠의 증감률을 계산하지 않는다.
- 캠페인 분석은 관측 지표와 입력한 제품·목표·고객을 연결한 로컬 규칙 기반 제안이다. 실제 시청자 구성·게시물을 분석한 결과는 아니다. 자연어 전반을 이해하는 모델이나 실제 콘텐츠 분석 기능이 아니다. 조건 초안을 사용자가 확인·수정해야 한다. 실제 모델의 생성 품질은 아직 검증하지 않았다.
- 로컬 미리보기는 공개 배포 주소가 아니다. 원격 저장소 공개 상태와 제출 여부는 [추적표](docs/REQUIREMENTS.md)에서 분리한다.

## AI 시연과 개발용 연결 코드의 구분

현재 화면은 외부 요청 없이 시연을 제공한다. 브리프는 문장에서 명시된 조건을 추출하고, 없는 조건은 수정 가능한 시작값이라고 알린다. 문의 시연은 원문의 금액·일정·사용권·직접 쓴 내용을 보존하고 표현을 다듬는다. 성과 요약은 직접 입력하거나 명시한 예시의 수치만 읽는다. 추천 순위는 별도 순수 함수가 계산한다.

`server/assistant.ts`, `.env.example`, 응답 파서는 향후 실제 모델 평가를 위한 개발용 코드로 남겼다. 현재 UI에서 호출하지 않는다. 키를 설정해도 현재 시연이 자동으로 실제 AI로 전환되지는 않는다. 향후 연결 시 서버 환경변수·입력 크기 검증·45초 제한·응답 검사·명시적 사용자 생성과 적용 단계를 사용한다. 실제 호출 성공·모델 품질·사용량은 이번 검증 결과로 주장하지 않는다.

온보딩 전환 4.2초(조건·예산·추천 기준의 3단계 안내)와 AI 시연 대기 0.9초는 흐름을 읽기 위한 표현 시간이다. 실제 처리 성능이나 AI 진행률이 아니다. 실제 CSV·Worker의 실패와 재시도 처리는 별도로 유지한다.
