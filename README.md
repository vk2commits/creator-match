# Creator Match

**브랜드 실무 마케터가 우리 제품에 맞는 후보를 이해하고, 근거를 확인한 뒤 문의하는 크리에이터 탐색 작업실.**

원본 CSV 200명의 지표를 조건·사용자 비중으로 비교한다. 후보별 적합 분석은 제품·고객·콘텐츠의 연결과 조율할 점을 설명하고, 선택한 질문을 문의 초안으로 전달한다. 기본 실행에는 계정·API 키·DB가 필요하지 않다.

현재는 **통합 분석·단계별 온보딩·자료 범위를 구분하는 검색을 적용한 상태**다. 캠페인별 성과 전체 경로와 사용자 최종 검토·공개 제출은 남아 있다. [분석 적용](docs/UNIFIED_ANALYSIS.md) · [온보딩 변경 이력](docs/ONBOARDING_REVIEW.md) · [검색 적용](docs/SEARCH_EVIDENCE.md).

## 3분 안에 살펴보기

1. 아래대로 실행하고 `http://127.0.0.1:5173/?demo`를 연다. 일반 캠페인과 분리된 탭 체험이다. 이 탭의 입력은 새로고침 후에도 유지된다.
2. **새 캠페인 → 예시 문장 넣기 → 캠페인 초안 만들기**를 누른다. 캠페인·고객 → 후보 조건 → 추천 기준을 한 단계씩 확인한다. 직접 입력도 가능하다. 예시의 뷰티·패션 / 1명당 200만 원 / 팔로워 1만~10만 조건은 추천 21명, 비용 미확인 3명이 나온다. 키워드를 추가하면 표시 수는 달라진다.
3. **민준브이로그180 → 적합 분석**. 첫 문단에서 발색·사용감 비교와 립 제품의 연결을 읽고, **제품에 관한 질문** 근거를 눌러 해당 광고 댓글·콘텐츠를 연다. 시우매거진155는 같은 캠페인에서도 일상 표현으로 조율할 점이 나온다.
4. **적합 분석으로 돌아가기 → 문의 질문 선택 → 제안 담아 문의하기**. 한 명에게 바로 문의 문안을 준비할 수 있다. 기존 문안이 있으면 추가할 제안을 미리 본다. 원래 문안·협업 상태는 보존한다. 실제 이메일·DM은 발송되지 않는다.
5. **기준·비중 변경**에서 프리셋 또는 직접 비중을 조정한다. 적용 전에는 기존 결과를 유지한다. 저장한 후보 중 최대 3명만 비교할 수도 있다.
6. 협업 관리에서 받은 견적·합의 비용·제작 상태를 기록한다. 게시 후 성과는 출처·확인일과 함께 입력한다. **저장하고 성과 리포트 보기**는 입력 창을 닫고 갱신된 결과를 보여준다.

**검토 리포트 내려받기**는 현재 분석을 Markdown으로 내보낸다. 앱 안 브라우저에서 파일 저장 완료는 확인하지 못했으며, 함께 제공하는 **리포트 내용 복사**는 실제 복사 내용을 확인했다. 웹앱 주소는 이 컴퓨터의 로컬 미리보기이며 공개 배포 주소가 아니다.

## 실행과 검증

Node.js **22.12 이상**, npm. 확인 환경: macOS / Node 25.5.0 / npm 11.8.0.

```sh
npm ci
npm run dev
```

터미널의 로컬 주소를 연다. `index.html`을 파일로 직접 열면 실행되지 않는다.

```sh
npm test         # 정책·데이터·저장·분석 근거 검사
npm run build    # 타입 확인과 배포용 파일 생성
npm run preview  # 생성 파일 로컬 확인
npm run analyze  # 데이터 감사·추천 비교 문서 재생성
```

최근 전체 자동 검사는 **15개 파일 200개 테스트 통과**다. 데스크톱 검증·타입/빌드·이전 독립 설치 재현 범위는 [QA](docs/QA.md)에 구분해 기록했다. 최신 확장 전체를 새 환경에서 재검증한 것으로 주장하지 않는다.

## 핵심 판단

**조건과 우선순위를 분리한다.** 예산·분야·팔로워는 자격 조건이고 참여율·조회수·평점·이력은 통과 후보의 비교 기준이다. 동일 플랫폼·규모 내 상대 위치를 사용하되 측정 정의·형식의 차이가 완전히 사라지는 것은 아니다. 비중은 사용자가 조절하며 학습한 최적값이 아니다. 수식과 대안 A/B/C는 [PRD](PRD.md), [비교 실험](docs/EVALUATION.md), [추천 설계 검토](docs/LOGIC_REVIEW.md)에 있다.

**모르는 정보를 0으로 만들지 않는다.** 이력이 없는 27명의 0원은 비용 미확인이고, 평점 공란은 미평가다. 유이력 173명의 평균 비용×건수와 누적액이 달라도 원본을 고치지 않는다. 예산은 제공 평균 비용으로 판단하며 현재 견적으로 보장하지 않는다.

**추천 순위와 콘텐츠 해석을 구분한다.** 콘텐츠는 제품을 어떤 방식으로 소개할지 검토하는 추가 근거다. 자료를 가진 후보에 점수를 더 주지 않는다. 적합 문단·근거 링크·문의 제안·리포트가 같은 분석 결과를 사용한다. 실제 고객 구성은 별도 확인 대상이고, 댓글의 구매 의향은 구매 실적이 아니다.

## 데이터와 AI의 현재 범위

- **원본:** 200명 CSV를 바이트 단위로 보존한다. 광고별 성과·SNS 주소·사진·실제 타깃 오디언스가 없다. 원본과 앱 복사본의 해시는 [데이터 감사](docs/DATA_AUDIT.md)에 있다.
- **추가 사례:** 5명의 콘텐츠·댓글·일부 연령 분포는 별도 편집 예시다. 두 이미지는 AI 생성물이다. 실제 SNS 관측·실제 인물 사진이 아니며 출처를 상세와 리포트에 표시한다.
- **직접 등록:** 게시물·댓글 자료는 CSV와 분리하고 후보별 공통 자료로 저장한다. 첫 등록부터 그 후보의 예시를 대체한다. 미입력 조회수와 미분류 댓글을 0으로 해석하지 않는다.
- **기본 AI 경험:** 브리프·문의 수정·성과 정리는 로컬 규칙이다. 검색과 적합 분석도 키 없이 실행된다. 실제 모델의 자연어 이해·정확도가 검증됐다는 뜻은 아니다.
- **선택적 실제 연결:** `.env.example`에 안내된 서버 환경변수를 설정하면 검색·후보 분석에 모델을 연결할 수 있다. 키는 `VITE_` 접두사나 공개 파일에 넣지 않는다. 서버 재시작 후 사용자 요청에 포함한 캠페인·근거 자료·선택 이미지를 처리한다. 입력 크기, 45초 제한, 응답·근거 ID를 확인한다. **이번 환경은 미설정이며 실제 응답 성공·품질·비용은 검증하지 않았다.** 정적 호스팅에는 이 로컬 서버 연결이 포함되지 않는다.
- **저장:** 일반 주소는 localStorage, `?demo`는 별도 sessionStorage. 캠페인별 조건·후보·문의·성과는 분리하고 채널 자료는 공통이다. 계정·클라우드 동기화·공동 편집은 없다.
- **집행 결과:** 사용자 기록은 추천 데이터와 합치지 않는다. 후보당 캠페인 내 최신 누적 성과 한 건을 저장한다. 자동 수집·성과 예측·총예산 최적화·실제 계약/메일·결제는 구현하지 않았다.

## 주요 구조

```text
src/policy.ts / domain.ts      추천 조건·계산·정렬의 기준
src/weights.ts                직접 비중과 합계100 유지
src/Onboarding.tsx / setup.ts  캠페인 설명·초안 검토·입력 보존
src/briefIntake.ts             명시된 조건의 로컬 추출
src/WorkspaceApp.tsx           캠페인별 작업실
src/CreatorRow.tsx             간결한 후보 목록
src/DiscoverySearch.tsx        자연어·키워드·이미지 입력
src/searchPolicy.ts            검색 근거·자료 부족·제외 판정
src/CandidateResults.tsx       모집단·검색 인원·빈 상태
src/review.ts                  화면·문의·리포트의 공통 분석
src/ContentDossier.tsx         통합 분석과 근거 탭
src/creatorContent.ts          별도 예시·등록 자료·범위별 집계
src/ContentEntry.tsx           자료 등록·댓글 분류 확인
src/Workflow.tsx               문의·협업·집행 결과
src/campaign.ts                기록과 성과 검증·비용 효율
server/research.ts             선택적 검색·후보 분석 모델 연결
public/data/                  원본 CSV의 바이트 동일 복사본
```

검증한 것은 계산·정책·근거 연결·기록 보존이다. 실제 추천 정확도, 광고 매출 개선, 사용자 시간 절감과 직관성은 아직 입증하지 않았다. 모바일 작업은 사용자 요청으로 범위에서 제외했다. 최종 제출 전에 사용자와 전체 요건·흐름·카피를 확인한다.
