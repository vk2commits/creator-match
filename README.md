# Creator Match

**브랜드 마케터가 크리에이터를 고르고, 선택 이유를 설명하고, 문의를 준비하는 웹앱입니다.**

한 명당 200만 원으로 립틴트 협업 후보를 찾는다면, 조회수가 높은 사람과 반응이 좋은 사람 중 누구에게 먼저 연락해야 할까요? Creator Match는 조건을 통과한 후보 안에서 마케터의 우선순위를 반영합니다. 추천 기준을 바꾸면 실제 순위와 설명이 함께 바뀝니다.

![실제 추천 화면 — 조건·기준·주요 지표를 한 목록에서 비교](docs/screens/results.png)

## 프로토타입 실행

Node.js **22.12 이상**과 npm이 필요합니다. API 키·로그인·데이터베이스 없이 실행됩니다.

```sh
npm ci
npm run dev
```

실행 후 **[프로토타입 열기](http://127.0.0.1:5173/?demo)**를 선택합니다. 이 주소는 실행한 컴퓨터에서만 열리는 로컬 주소입니다. 공유 호스팅 주소가 아닙니다. 터미널에 다른 포트가 표시되면 그 주소에 `?demo`를 붙입니다.

일반 경로는 캠페인을 브라우저에 보관하고, `?demo`는 별도 탭 저장 공간을 사용합니다. HTML 파일을 직접 열지 않고 위 방식으로 서버를 실행해 주세요.

## 먼저 확인할 세 장면

1. **조건을 정합니다.** ‘예시 문장 넣기 → 캠페인 초안 만들기’ 후 캠페인·고객 → 후보 조건 → 추천 기준을 확인합니다. 뷰티·패션, 마이크로, 1명당 200만 원을 적용하면 예산 내 **21명**, 견적 필요 **3명**이 나옵니다.
2. **목적이 달라지면 순서가 달라집니다.** 조회수 우선의 첫 후보는 **정은매거진77**입니다. 결과 상단의 ‘기준·비중 변경’에서 참여율 우선을 적용하면 **서연리뷰66**이 첫 후보가 됩니다. 후보 자격은 그대로이고 비교 기준만 바뀝니다.
3. **결과가 없어도 다음 행동이 있습니다.** 같은 조건에서 예산을 1원으로 바꾸면 예산 내 후보가 없습니다. **540,000원** 제안을 적용하면 **소라TV177 한 명**이 나옵니다. 비용 미확인 후보는 별도로 남습니다.

선택 기능은 **민준브이로그180 → 적합 분석 → 근거 확인 → 제안 담아 문의하기**로 확인할 수 있습니다. 이 후보의 콘텐츠·댓글은 별도 편집 예시입니다. 문의·협업·성과는 로컬에서 기록하며 실제 이메일·DM을 발송하지 않습니다.

## 왜 이렇게 추천하는가

**조건 충족과 추천 순위를 분리했습니다.** 예산·분야·규모를 통과했다고 다시 점수를 더하지 않습니다. 통과한 후보의 참여율·조회수·평점·경험을 비교합니다. 싼 비용 자체에도 보너스를 주지 않습니다.

**플랫폼과 규모가 비슷한 후보끼리 비교합니다.** 참여율·조회수는 원본의 동일 플랫폼×규모 안에서 상대 위치로 환산합니다. 절대 조회수가 큰 채널만 앞서는 현상을 줄이기 위한 판단입니다. 대신 절대 차이가 압축되고 기간·콘텐츠 형식 차이는 남습니다.

**시작 비중을 공개하고 바꿀 수 있게 했습니다.** 조회수 우선은 참여율20·조회수55·평점15·경험10%입니다. 모든 광고주에게 최적인 숫자라는 근거는 없습니다. 목표별 출발점으로 두고 직접 조절·원지표 재정렬을 제공합니다.

**모르는 비용을 0원으로 해석하지 않았습니다.** 원본 200명 중 27명은 집행 이력 0·평균 비용 0·평점 공란입니다. 별도 견적 필요 후보로 남기고 평점은 미평가로 표시합니다. 협업 이력이 있는 173명의 평균 비용×건수와 누적액 불일치도 수정하지 않고 필드 사용 정책을 정했습니다.

두 후보의 원본 수치·점수 기여를 따라갈 수 있는 [실제 계산 사례](PRD.md#64-같은-두-후보가-왜-뒤바뀌는가)와 [전체 수식·트레이드오프](PRD.md#6-추천-로직과-설계-근거)를 PRD에 담았습니다.

## 무엇을 검증했는가

같은 조건에 A=팔로워순, B=전체 집단 상대 점수, C=플랫폼×규모 상대 점수를 비교했습니다. 150개 조건 중 후보가 있는 76개에서 C의 조건 위반은 0건이고 A–C의 1위는 45개에서 달랐습니다. 균등 비중의 상대 ±20% 변경 608회에서는 1위가 35회 바뀌었습니다.

이는 정책 준수·계산 재현·민감도를 검증한 결과입니다. 실제 광고 성과 정답이 없어 추천 정확도나 매출 개선율로 해석하지 않았습니다. [대안 실험](docs/EVALUATION.md) · [검증 기록](docs/QA.md)

```sh
npm run check       # 자동 테스트, 타입 검사, 빌드
npm run preview     # 빌드 결과 열기
npm run analyze     # 데이터 감사와 대안 비교 재생성
node --import tsx scripts/review-logic.ts
```

macOS / Node 25.5.0 / npm 11.8.0에서 테스트 **200개**, 타입 검사와 빌드를 통과했습니다. 별도 빈 폴더에서 기존 npm 캐시로 설치·검사도 확인했습니다.

## 구현 범위

- **추천에 쓰는 데이터:** 제공 CSV 200명·11필드. 원본 해시는 [데이터 감사](docs/DATA_AUDIT.md)에 기록했습니다.
- **별도 설명 자료:** 콘텐츠 예시 5명·AI 생성 이미지 2개. 실제 수집 정보와 구분하며 추천 점수에 가산하지 않습니다. 화면 이미지는 실제 실행을 캡처한 것입니다.
- **제품 내부 AI:** 문장 정리·문의·성과 요약은 현재 로컬 규칙입니다. 검색·후보 분석에는 선택적 모델 연결 코드가 있습니다. `.env.example`의 서버 변수로 설정하며 실제 모델 품질·비용·지연은 이번 환경에서 검증하지 않았습니다. API 키를 공개하거나 `VITE_` 변수에 넣지 않습니다.
- **협업·성과:** 캠페인별 수동 기록입니다. 실제 발송·자동 수집·로그인·결제·공동 편집·모바일 작업은 제외했습니다. 미확정 온보딩 입력은 새로고침으로 사라질 수 있습니다.
- **남은 검증:** 실제 사용자 이해도, 모델 연결, 두 캠페인 성과 입력 전체 경로, 다운로드 완료, 공개 GitHub의 Mermaid 렌더링입니다. 구현과 검증을 같은 의미로 쓰지 않았습니다.

경쟁사에서는 탐색에서 협업으로 이어지는 업무와 근거 확인 방식을 참고했습니다. 이 결과물의 초점은 **사용자의 기준, 실제 계산, 설명, 확인할 행동을 연결하는 것**입니다. 경쟁사의 내부 추천이나 성과를 재현했다는 주장은 아닙니다. [경쟁사 심층 조사](docs/COMPETITOR_DEEP_DIVE.md)
