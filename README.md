# Creator Match

**브랜드 실무 마케터가 후보의 선정 이유부터 문의·협업·집행 결과까지 이어가는 크리에이터 탐색 프로토타입.**

캠페인 브리프 → 후보 조건 → 추천 기준·직접 비중 → 탐색·비교 → 문의 준비 → 협업 관리 → 성과 리포트로 이어진다. 제공된 더미 200명의 추천과 수동 기록은 API 키·계정·DB 없이 실행한다. 제품 내 AI는 로컬 서버에 키를 설정한 경우 사용하는 선택 기능이다.

## 3분 안에 살펴보기

1. 아래 명령으로 실행한다.
2. **캠페인 설정**에서 캠페인명·제품·목표를 작성하고 마지막 단계에서 참여율 우선을 선택한다. 재방문이라면 상단 링크 또는 `/#setup`으로 다시 연다. 뷰티·패션, 1만–10만 미만, 2,000,000원을 적용한다.
3. **서연리뷰66**을 담고 **조회수 우선**으로 바꿔 먼저 나오는 **정은매거진77**을 담는다. **담은 후보 검토**에서 두 명을 비교 선택한다.
4. **2명 비교하기**에서 참여율 8.1% 대 6.5%, 평균 조회수 10,003회 대 35,172회를 비교한다. 한 명은 **문의 후보**, 다른 한 명은 **보류**로 지정하고 직접 이유를 적는다.
5. **문의 후보 검토안 만들기 → 팀 검토안 복사**로 팀 문서에 옮길 결과물을 확인한다. 문의를 실제로 발송하지 않는다. 후보가 한 명이면 상세의 **검토 상태 → 문의 후보 → 선정 이유 정리**으로 바로 진행한다.
6. **비중 조절**에서 조회수 100%로 바꿔 상위 3명 미리보기를 본다. 취소하면 기존 기준을 유지한다. 적용하면 같은 21명 중 순서가 바뀐다. **비용 미확인**의 3명은 무료 후보가 아니다.

7. 팀 검토안의 **문의 준비로 이동** 또는 왼쪽 **협업 관리**에서 문안을 작성하고 복사한다. 직접 확인한 연락처를 입력하면 이메일 초안을 열 수 있다. 복사와 초안 열기는 발송이 아니다.
8. **성과 리포트 → 예시 리포트 보기 → 상세 결과 보기**에서 크리에이터별 지표·비용 효율을 확인한다. 예시는 내 기록에 저장되지 않는다. 실제 기록은 **내 기록으로 돌아가기 → 성과 기록**에서 입력한다.

첫 설정의 **예시 캠페인 둘러보기**는 균등 기준을 사용한다. 브리프·조건·사용자 비중·보관·비교·판단 상태·이유·협업 기록은 이 브라우저에 저장된다. 보관 인원 제한은 없고 동시 비교는 최대 3명이다. 온보딩 재진입은 기존 저장을 삭제하지 않는다.

## 실행

Node.js **22.12 이상**, npm이 필요하다. 검증 환경은 macOS / Node 25.5.0 / npm 11.8.0이다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 연다. 기본 주소는 `http://127.0.0.1:5173/`다. `index.html`을 파일로 직접 열면 앱이 실행되지 않는다.

```sh
npm test              # 정책·데이터·저장·로딩 테스트
npm run analyze       # 데이터 감사·추천 비교 문서 재생성
npm run build         # 타입 확인 + dist 생성
npm run preview       # 생성한 dist를 로컬에서 확인
```

별도 폴더에서의 의존성 설치·테스트·빌드 재현과 실제 브라우저 검증 범위는 [QA](docs/QA.md)에 기록한다.

## 세 가지 핵심 판단

**조건과 우선순위를 분리했다.** 예산·분야·팔로워는 반드시 충족할 조건이고, 참여율·조회수·평점·이력은 그 안에서 비교할 기준이다. 참여율 우선, 조회수 우선, 협업 이력 우선, 균등 비교 중 사용자가 선택하거나 네 지표의 비중을 직접 조절한다. 가중치는 설계 가정이며 성과를 학습한 최적값이 아니다.

**모르는 정보를 가격 0원·평점 0점으로 바꾸지 않았다.** 집행 이력 없는 27명은 비용 미확인으로 분리한다. 평균 비용은 과거 참고값이며 현재 견적이 아니다. 평점 공란은 미평가다.

**계산을 읽히기보다 선택을 돕는다.** 목록에는 원지표, 상세에는 추천 이유·추가 확인 사항, 필요할 때 펼칠 수 있는 계산 근거를 둔다. 후보 비교에서 문의 대상과 보류를 구분하고, 팀에 설명할 검토안으로 연결한다. 첫 UI의 문제와 지원자의 실제 피드백은 [UX 검토](docs/UX_REVIEW.md) 및 [AI 활용 기록](AI_USAGE.md)에 남겼다.

## 알고 있는 한계와 트레이드오프

- 제공 데이터에는 채널 URL·사진·실제 전환·타깃 오디언스·관측 기간이 없다. 더미 인물의 링크와 광고 성과를 발명하지 않는다.
- 동일 플랫폼×규모 상대 위치로 비교하되 형식·카테고리·측정 정의 차이는 남는다. 원지표와 정렬을 같이 제공한다.
- 유이력 173명의 평균 비용×건수와 누적액이 일치하지 않는다. 원본은 유지하고 제공 평균으로만 예산을 판정한다.
- 집행 건수는 평점 응답 수가 아니다. 평점 표본이 없는 상황에서 정교한 통계 보정을 가장하지 않는다.
- 점수의 안정성·정책 준수는 검증했지만 실제 추천 정확도·매출 개선·사용자 시간 절감은 검증하지 않았다.
- 인증·실제 문의·계약·다수 크리에이터 총예산 최적화는 제외했다. 첫 설정은 가입 직후를 가정한 데모다.
- 팀 검토안은 화면 확인·복사로 제공한다. 후보별 문의 이유를 작성해야 복사할 수 있다. 불확실했던 파일 다운로드 경로는 이번 흐름에서 제거했다.
- 후속 검토에서 발견한 집단 확대의 중간값·신규 후보의 예산 설명을 수정하고 회귀 검증했다. 현재 86개 자동 테스트·빌드 통과. [QA](docs/QA.md)에 검증 범위와 사용자 리뷰·공개 제출 등 남은 항목을 구분했다.
- 단일 캠페인 작업실이며 1명당 콘텐츠 최신 누적 성과 1건을 저장한다. 다중 캠페인·여러 콘텐츠·시계열·팀 권한·실제 발송·결제·자동 수집은 제외했다. Pro의 가치는 이런 반복 운영 업무의 확장 가설이며 유료 잠금은 구현하지 않았다.
- 추천용 원본 지표와 집행 후 직접 입력한 결과는 서로 다른 데이터다. 기록은 추천 점수에 다시 반영하지 않는다. 원본 평균과 실제 콘텐츠의 증감률을 계산하지 않는다.
- 실제 AI 생성 품질은 API 연결 후 검증해야 한다. 현재는 미연결 안내와 입력·응답 계약을 검증했으며 실제 모델 호출 성공을 주장하지 않는다.
- 로컬 미리보기는 공개 배포 주소가 아니다. 원격 저장소 공개 상태와 제출 여부는 [추적표](docs/REQUIREMENTS.md)에서 분리한다.

## 선택 기능: 제품 내 AI 연결

브리프 정리, 문의 문안 다듬기, 입력 성과 요약을 제공한다. 핵심 추천·문의 기본 문안·성과 기록은 연결 없이도 동작한다.

1. `.env.example`을 `.env.local`로 복사한다.
2. `OPENAI_API_KEY`를 로컬에서 직접 입력한다. 키를 문서·채팅·Git에 넣지 않는다. 기본 모델은 `gpt-4.1-mini`이며 `OPENAI_MODEL`로 변경할 수 있다.
3. 개발 서버를 다시 실행한다. AI 패널의 **연결 다시 확인**을 누른다.
4. 전달할 자료를 확인하고 **AI로 생성**을 누른다. 생성된 초안을 직접 수정·적용한다. 사용량은 연결한 API 계정에 발생한다.

키는 Vite의 서버 측 연결에서만 사용하며 `VITE_` 접두어를 쓰지 않는다. `/api/assistant`는 로컬 호스트 전용이며 공개 서버 API가 아니다. Responses API에 `store:false`로 요청하지만 이를 제공사의 모든 보존 정책이 없다는 의미로 설명하지 않는다. static 파일만 배포하면 AI 엔드포인트는 없으므로 연결 필요 안내가 표시된다. 공개 운영에는 별도의 인증·사용량 제한·권한·비밀 관리 설계가 필요하다.

지금은 실제 키 없이 UI·파서·오류 경계를 검증했다. AI 응답이 원자료를 보존하는지 확인하는 실호출 검증은 남아 있다.
